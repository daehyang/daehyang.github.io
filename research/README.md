**2026-09-30 — 세 계열을 한 번씩 다 훑고, 도엽마다 판독 문서를 두었습니다.**
『해동지도』 13종, 《1872년 지방지도》 9종, 『대동여지도』 2면입니다.

**2026-10-01 — 아홉 도엽을 2차로 다시 읽었습니다.** 「한 번 훑은 것」과 「두 번 읽은 것」이
얼마나 다른지가 하루 만에 드러났습니다.

> **방법 하나가 섰습니다 — 「같은 도엽 안의 자[尺]」.**
> `峴`·`峙`·`嶺` 은 왼쪽(또는 왼쪽 위) `山` 부수 하나로 갈립니다. 흐린 글자를 더 키우는
> 대신 **같은 도엽에서 또렷하게 쓰인 같은 글자를 찾아 나란히 대 봅니다.**
> 하루에 다섯이 바뀌었습니다 — 연기 둘 철회, 회인 넷 확신 상승과 하나 추가,
> 회덕 `馬峴` 철회(자는 면별 거리표의 `縣內面`), 회덕 `于峙嶺` 셋째 글자 흔들림.

2차 판독에서 나온 것은 대조표 17장 변경 이력에 날짜별로 있습니다. 큰 것만 —

- **철회 둘** — 회덕 `馬峴`(고개가 아니라 `縣內面`), 연기 `金沙峴`·`城峴`
- **새 고개 다섯** — 문의 `城峴`·`栗峴`, 옥천 `九也峙`, 연산 `□□峴`, 회인 `車嶺`
- **「고개가 없다」를 두 번 거둠** — 옥천·연산
- **봉수 노선이 세 고리에서 다섯으로**, `烽臺`·`月伊` 두 미판독이 풀림
- **1872년 계열은 면마다 리 이름을 다 적습니다** — 옥천·회덕·진잠에서 확인

**2026-10-01 덧붙임 — 1872년 계열에 빠진 도엽이 셋 있었습니다.**
커먼즈 1872년 분류(도엽 200장)를 해동지도 열세 고을과 맞춰 보니
**회인현지도**·**연기현지도**, 그리고 **문의현지도 둘째본**(문의는 도엽이 두 장입니다)이
빠져 있었습니다. 셋 다 받아 판독 문서를 두었습니다. 그 가운데 —

- **회인 기문의 `後爲懷德兼任官`** — 회인이 한때 **회덕의 겸임지**였습니다
- **문의 둘째본의 `漏峴 自官東距十里`** — `漏峴`(회인 길)과 `弘峙`(회덕 길)가 **다른
  고개**임이 가려졌습니다
- **1872년 도엽을 해동지도의 고을 이름으로 찾으면 개명한 고을을 놓칩니다** —
  해동지도 `이산현`은 1872년에 `노성현`입니다

**2026-10-01 덧붙임 둘 — 진산군 두 계열을 맞붙여 읽었습니다.**
『해동지도』 기문의 **`新目峙`** 가 1872년 도엽의 **`思睦峙`** 와 같은 고개(동쪽 옥천 길)임이
확인됐고, 그 길에 **고개 이름 가운데의 `目`·`睦`·`項` 은 모두 우리말 「목」**이라는
읽기가 섰습니다 — 한 고을에서 같은 말에 넉 자가 쓰였습니다. 그 밖에 —

- **1872년 진산군지도는 경계 길 주기를 방위마다 답니다** — 동 `思睦峙…沃川界四十里` ·
  서북 **`馬項西北至忠淸道公州界`** · 서 `…連山界十里`. **1872년에도 북쪽은 공주**입니다
- **`鷄峴` 후보 자리가 사라졌습니다** — 2026-09-30 에 세운 (0.74, 0.50)은 고개 주기가
  아니라 **리(里) 패**였습니다
- **`隘口` 확정을 철회했습니다** — 해동지도 진산군의 두 글자는 `阝` 변이 둘이라
  `隘口` 와 획이 맞지 않습니다(`陰阨`〔?〕). **자[尺]를 대기 전에 획부터 센다**는
  원칙을 대조표 2장에 적었습니다
- **`方古峙` 가 미비정을 벗었습니다** — 미군 1:50,000 「Kumsan」 도엽에 **`方峴里`**
  로 남아 있습니다(지금 **금산군 복수면 방현리**). 기문의 `方古介`→「방고개」 읽기가
  마을 이름으로 확인됩니다

남은 것은 **잔글씨 판독**(규장각 고해상 원본이 필요한 자리)과 **여지도서 부도**,
그리고 **1872년 공주목지도의 면별 리 이름**(커먼즈 썸네일로는 모자랍니다 — 대조표 10장).
어느 도엽이 어디까지 됐는지는 [`고지도-목록.md`](고지도-목록.md) 의 「채록 상태」 칸에
있습니다.

## 고치는 방법

- **`main` 에 바로 고칩니다.** 이 저장소의 규칙 그대로입니다(`../CLAUDE.md`). 조사 문서도
  예외가 아닙니다 — 사이트에 나가지 않으므로 잘못 적어도 홈페이지가 상하지 않습니다.
  GitHub 웹에서 문서를 열고 연필 아이콘을 누르면 바로 고칠 수 있습니다.
- 다만 **사이트에 나가는 파일**(`_config.yml`, `_layouts/`, 페이지 `.md`)을 함께 건드렸다면
  푸시 전에 로컬 빌드로 확인합니다. 방법은 `../CLAUDE.md` 의 "로컬 빌드".
- 고친 내용은 문서 끝 **변경 이력**에 한 줄 남깁니다.

## 지명제보 게시판과 Issues — 가르는 기준

> **지명 이야기는 게시판에서 하고, 손을 움직이는 일은 Issues 에서 합니다.**

|  | 지명제보 게시판 | Issues |
|---|---|---|
| **지명** | **의논** — 제보, 판독 의견, 비정 토론 | **실행** — 등재 발의·심의·확정, 문서 반영 |
| **그 밖** (사이트·회지·사무) | — | 전부 |

가르는 축이 둘입니다. **무엇에 관한 것인가**(지명이냐)와 **의논이냐 실행이냐**.

- 「할머니께 들은 고개 이름이 있습니다」 · 「이 글자는 `于` 가 아니라 `牛` 로 보입니다」
  · 「`雞峙` 가 삼괴동 닭재인가」 → **게시판**
- 「○○ 도엽을 처음부터 끝까지 훑는다」 · 「결론을 대조표 3장에 반영한다」
  · 「메뉴에 항목을 하나 넣는다」 → **Issues**

**게시판은 누구나 열 수 있고, Issues 는 연구진의 작업 목록입니다.** 그래서 Issues 는
닫을 조건이 뚜렷한 것만 둡니다 — 이슈 본문에 **「무엇을 하면 닫히나」** 를 적습니다.

### 게시판에서 Issues 로 넘어가는 두 자리

**① 등재** — 의논이 끝나 등재할 만해지면 **`internal` 저장소의 「지명 등재 발의」** 서식으로
엽니다. 이 저장소가 아닙니다 — 거기서 `/등재` `/확정` 댓글 명령이 돌고 대장이 고쳐집니다.
넘어가는 **문턱은 `internal/docs/decisions.md` 의 0017** 입니다(자리·확신도 `상`·근거의
성격·표제어 넷).

**② 문서 반영** — 판독이나 비정의 결론을 대조표·판독 문서에 적는 일은 이슈로 둡니다.
커밋 메시지의 `Closes #N` 으로 닫히기 때문입니다. **게시판 글은 커밋으로 닫을 수 없습니다.**

```
지명제보 게시판 (공개·누구나)      의논 — 제보 · 판독 · 비정
        ↓  0017 의 문턱을 넘으면
internal 이슈 「지명 등재 발의」    실행 — 심의 · 표결 · /확정 → 대장
        ↓  자동
홈페이지 공개 목록 /placenames/
```

게시판 글에 확인할 값이 생기면 **Create issue from discussion** 으로 올려도 됩니다.
출처가 자동으로 이어집니다.

## 세 자리 — 문서 · 이슈 · 게시판

문서 안에서 말다툼하지 않습니다. 자리가 셋이고 담는 것이 다릅니다.

| 자리 | 담는 것 |
|---|---|
| **문서** (대조표·판독 문서) | **결론과 근거만** |
| **Issues** | 연구진의 과제 — 닫을 조건이 있는 것 |
| **게시판** | 바깥에서 들어오는 것 — 제보·의견, 오가는 말 |

- **일 하나가 이슈 하나**입니다. 결론이 나면 문서에 반영하고 이슈를 닫습니다.
- 게시판과 이슈 댓글 모두 **그림을 끌어다 놓을 수 있습니다.** 확대한 사진은 거기 붙입니다.
- 남은 일을 문서 안에 체크리스트로 만들지 않습니다. 가장 자주 바뀌는 것을 문서에 두면
  문서가 낡습니다.

## 그림 — 올리지 않고 링크로 겁니다

**원본 도엽을 이 저장소에 올리지 않습니다.** 고지도 스캔본은 한 장에 수십 MB 이고,
git 은 한 번 커밋한 파일을 지워도 히스토리에 영구히 남깁니다. 대신 **위키미디어 공용
(Wikimedia Commons)에 있는 것을 링크로** 겁니다.

**다만 판독 근거로 잘라 낸 작은 조각은 [`crops/`](crops/) 에 둡니다.** 판독은 자주 뒤집히고,
뒤집을 때 근거 그림이 저장소 안에 있어야 다른 사람이 바로 확인합니다. 크기·이름·넣는 방법은
[`판독-기록-형식.md`](판독-기록-형식.md) 의 "잘라낸 그림" 절에 있습니다.

주소는 두 가지를 함께 적습니다.

| 쓰임 | 주소 틀 |
|---|---|
| 그림을 본문에 걸 때 | `https://commons.wikimedia.org/wiki/Special:FilePath/<파일명>?width=1000` |
| 출처·라이선스를 가리킬 때 | `https://commons.wikimedia.org/wiki/File:<파일명>` |

```
[![진산군지도](https://commons.wikimedia.org/wiki/Special:FilePath/<파일명>?width=1000)](https://commons.wikimedia.org/wiki/File:<파일명>)
```

- 파일명의 한글·괄호는 URL 인코딩합니다(`전` → `%EC%A0%84`). 커먼즈 파일 문서에서
  주소를 복사하면 이미 인코딩되어 있습니다.
- `?width=` 로 크기를 줄여 겁니다. 원본은 수천 픽셀이라 그대로 걸면 문서가 무겁습니다.
- **출전은 링크가 아니라 자료명과 소장처로 적습니다.** 커먼즈 파일은 지워지거나 이름이
  바뀔 수 있습니다. 링크가 깨져도 무엇을 본 것인지 남아 있어야 합니다.
- 커먼즈에 없는 자료는 링크하지 말고 **어디서 볼 수 있는지만** 적습니다(규장각 등).
  기관 원문 뷰어는 주소가 자주 바뀌어 링크가 오래가지 않습니다.

## 지켜야 할 것

- **여기는 공개 저장소입니다.** 개인 연락처, 미공개 회의 내용, 발간 전 원고를 넣지 않습니다.
  그런 것은 `internal` 저장소에 둡니다.
- **front matter 를 넣지 않습니다.** 없으면 Jekyll 이 정적 파일로 다루어 `exclude` 와 겹쳐
  이중으로 안전합니다. Liquid 태그도 쓰지 않습니다.
- **조사 메모는 확정 자료가 아닙니다.** 각 문서 첫머리에 그 사실을 적어 둡니다.
- **대장은 여기서 고치지 않습니다.** 근거가 갖춰진 항목은 `internal` 저장소의
  "지명 등재 발의" 이슈로 넘깁니다. 접근 권한이 없으시면 연구회로 알려 주십시오.
